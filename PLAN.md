# Blu Visual Teacher — Project Plan (Codestorm: Unlox 24hr Hackathon)

## 1. The Challenge, Restated
Build a local-first, offline engine: typed concept → 30–90s narrated, animated lesson in English + 2 Indian languages. Plays in-browser, exports as 720p H.264 MP4.

**Hard rules that constrain every decision below:**
- No external AI APIs (no OpenAI/Gemini/Claude/ElevenLabs/Google Translate/cloud voices)
- Fully offline, Wi-Fi off, during actual execution
- CPU-only laptop, 8–16GB RAM
- LLM outputs JSON data only — never executable code
- Every model/voice/asset must be listed in README with license

## 2. Non-Negotiable Architecture Rule
**Audio sets scene length, not the reverse.**
Pipeline dependency: `JSON plan → per-scene audio generation → scene duration = audio length + pause → visuals rendered to that duration`.
Parallelism happens **across scenes** (scene 3 renders while scene 1 composites), never across the audio→visual dependency within a single scene. Violating this breaks caption/narration sync, which is scored under both "Working End-to-End" (25%) and "Teaching Quality" (20%) — the two heaviest rubric items.

## 3. Stack Decisions (locked)

| Stage | Choice | Why | License to verify |
|---|---|---|---|
| Lesson Planner | Local LLM via Ollama (Qwen2.5-7B-Instruct or Phi-3.5-mini, GGUF, Q4_K_M) + GBNF grammar / JSON schema constraint | Structured JSON output, fast on CPU, no per-language model-juggling | Check Qwen2.5/Phi-3.5 license terms |
| Schema validation | JSON Schema check in-app; hardcoded fallback lesson on failure | Required by organizers (Gate 1 milestone) | N/A |
| Translation (if needed) | `sarvam-translate:v1` (open-weights, GGUF via llama.cpp) | Confirmed open-weights, offline-capable, Indic-language coverage | Apache 2.0 — confirm on model card |
| TTS / Narration | Piper TTS (primary) | Fast, small, fully offline, proven Hindi/Indic voices | MIT — confirm per-voice license |
| STT | **None** — not needed | Narration text is already known (generated by planner); re-transcribing is redundant and adds a failure point | N/A |
| Captions | Derived from TTS word/phoneme timestamps (Piper) or estimated via word-count × speaking rate per language | Avoids a second STT pass | N/A |
| Visual Engine | React + SVG + CSS, 3 scene types: Title Card, Diagram w/ Labels+Arrows, Code Walkthrough | Matches organizer spec exactly; no generative video | N/A |
| Export | Browser canvas capture (MediaRecorder) or headless Puppeteer + ffmpeg mux | Both offline, no cloud dependency | ffmpeg: LGPL/GPL depending on build |

**Explicitly rejected:**
- **Colibri / large MoE models** — built for 744B-class frontier models (~370GB+ weights even quantized); wrong tool for a lightweight planner/TTS pipeline on a hackathon laptop.
- **Sarvam Edge** — no confirmed public download path as of this writing; API-key-gated products found in docs are cloud calls, which violate the no-external-API rule.
- **Whisper (any variant)** — unnecessary; you generate the narration text, you don't need to transcribe it back.
- **Native Android app** — splits engineering time across two deployment targets in a 24h window; rubric doesn't score platform, only the 5-stage pipeline. Browser-only unless core pipeline is done with hours to spare.

## 4. Risk Register
| Risk | Mitigation |
|---|---|
| TTS quality/speed varies badly by target language | Test Piper against your actual 2+ chosen Indian languages by **hour 2**, not hour 15 |
| Planner LLM produces malformed JSON | Grammar-constrained decoding (GBNF) + schema validator + hardcoded fallback lesson (organizer-mandated) |
| Sync drift between audio/captions/visuals | Enforce the Section 2 dependency order — no exceptions for "speed" optimization |
| RAM overflow on 8GB machines | Dynamic quant selection by available RAM (reference: Uktam.ai's Q4_K_S/Q2_K switch pattern) |

## 5. Timeline (organizer milestones, annotated)
- **0–5h (Gate 1):** Hardcoded sample lesson, full pipeline, exported as MP4. This beats a "clever but non-functional" system per organizer pro-tip — do not skip or rush this.
- **5–10h:** Ollama integration, schema validation, fallback logic.
- **10–15h:** Visual engine, player controls, all 3 scene types.
- **15–20h:** TTS integration, script fonts for Indic languages, translation if used, ffmpeg export pipeline.
- **20–24h:** Feature freeze. Offline testing (Wi-Fi actually off). Rehearse the 5-min live demo + judge-assigned topic flow.

## 6. Open Questions Before You Start Building
- Final 2 target Indian languages (determines whether Piper alone suffices or `sarvam-translate` is needed in the loop)
- Confirm Qwen2.5-7B / Phi-3.5-mini quantized model actually fits comfortably in your team's RAM budget — test, don't assume
