# Offline RAG + Dual-Engine OCR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a student upload a PDF of up to thousands of pages (digital or scanned). It is OCR'd by Tesseract and Unlimited-OCR, combined per page, chunked and indexed. A large offline library is also indexed. Both feed the existing `knowledge.retrieve()` so the lesson is built from them.

**Architecture:** New packages `backend/app/ocr/` (triage, Tesseract pass, Unlimited-OCR pass, arbiter, ingestion) and `backend/app/rag/` (chunker, SQLite-FTS5 + FAISS collections, e5 embedder, bge reranker, hybrid search). These packages own their routes through an `APIRouter` in `app/routes_rag.py`. `knowledge.retrieve()` gains an optional `upload` argument and delegates to `rag.search` when new collections exist; the existing `data/kb` index keeps working unchanged.

**Tech Stack:**
- Python 3.12 (`backend/venv`)
- torch (CUDA 12.8 wheels), transformers==4.57.1, PyMuPDF, pytesseract + Tesseract 5
- faiss-cpu, sentence-transformers, rapidfuzz, datasets, pytest

**Spec:** `docs/superpowers/specs/2026-10-27-rag-ocr-design.md`

## Global Constraints

- Runs with Wi-Fi off. All models and data live under `models/` and `data/`. Set `HF_HUB_OFFLINE=1` at runtime.
- Python 3.12 venv at `backend/venv`. Do not use Python 3.14.
- Unlimited-OCR requirements are pinned from its model card: torch 2.10 (cu128 build), torchvision 0.25, transformers==4.57.1, einops==0.8.2, addict==2.4.0, easydict==1.13, pymupdf==1.27.2.2.
- Upload limits: max 2 GB, max 5,000 pages. Encrypted PDFs are rejected.
- Chunks are ~350 tokens with 50-token overlap. Tables and display equations are never split.
- Embedder `intfloat/multilingual-e5-small` with prefixes `query: ` / `passage: `. Reranker `BAAI/bge-reranker-v2-m3`.
- RRF k=60. Retrieval candidates: 50 keyword + 50 vector. Final k=8. In scope `both`, the library contributes ≤ 2 passages. Low-confidence pages are weighted ×0.8.
- Arbiter thresholds:
  - reject Unlimited-OCR output if a 30-token n-gram repeats ≥ 3 times;
  - reject it if its word count is < 0.5× or > 2× Tesseract's when Tesseract confidence ≥ 80;
  - Tesseract wins when it is ≥ 0.10 better on script validity or on lexicon hit rate;
  - agreement < 0.6 marks the page low_confidence.
- Only one big GPU model at a time: Unlimited-OCR (6.7 GB) and the Ollama LLM never overlap.
- Files owned by session `dhiraj-shetty-26`: `planner.py`, `pipeline.py`, `main.py`, `translate.py`, `web/`, `backend/.env`. Do not edit them. Task 12 hands the integration lines to that session.
- `knowledge.retrieve(concept)` stays backward compatible and still returns `list[Passage]`. `Passage(title, section, text, url, source, score)` is unchanged.

## Review Focus

1. **A PDF whose pages are mostly images but carry a thin invisible text layer** (typical of scanned books with bad embedded OCR). Expect the page to be treated as scanned, not trusted as digital. → Task 2 test `test_garbage_text_layer_is_scanned`.
2. **A student re-uploads the same PDF, or the server restarts mid-OCR.** Expect no repeated work: OCR resumes from the cache. → Task 9 test `test_resume_uses_cache`.
3. **A lesson is requested while OCR pass 2 is holding the GPU.** Expect OCR to yield within one batch and the lesson not to run out of GPU memory. → Task 5 test `test_ocr_yields_to_urgent`.
4. **A Hindi or Telugu PDF searched with an English concept, or the reverse.** Expect cross-lingual hits through the multilingual embeddings. → Task 7 test `test_cross_script_query_still_hits_vector`.
5. **A concept the PDF does not cover.** Expect `[]` from the upload scope and library passages instead, never padding with irrelevant upload chunks. → Task 8 test `test_irrelevant_upload_returns_library_only`.

**Spec deviation (deliberate):** §7 step 1 (translating Indic queries with IndicTrans2 before search) is replaced by multilingual-e5 cross-lingual search plus FTS on the original script. `translate.py` belongs to the other session and is changing to NLLB; this avoids depending on it. Revisit only if the Task 13 benchmark shows poor cross-lingual recall.

    - `"PDF has more than 5,000 pages"`
    - `"PDF is password-protected"`
    - `"Not a readable PDF"`
  - `file_sha(path: Path) -> str`, sha256 hex, first 16 characters
  - `resolve_focus(toc: list[TocEntry], n_pages: int, focus: str | None) -> list[int]`. It understands `"pages 120-135"`, `"page 7"` and `"chapter 4"` (the 4th level-1 TOC entry's range), and otherwise matches TOC titles by rapidfuzz `partial_ratio ≥ 80`. Returns 1-based pages; `[]` if nothing matches.
  - `priority_order(n_pages: int, toc_pages: list[int], focus_pages: list[int], tess_conf: dict[int, float]) -> list[int]`: TOC/front pages first, then focus pages, then by ascending Tesseract confidence, then the rest in page order. No duplicates.
  - `ingest_pdf(path: Path, lang: str | None, focus: str | None, progress: Callable[[str, float], None], *, unlimited=None, embedder=None) -> dict`. It runs pass 1 synchronously and returns `{"sha", "title", "pages", "digital", "scanned", "toc": [...], "focus_pages": [...]}`. It then starts the pass-2 upgrader thread, unless `unlimited is False` (used in tests).
  - `upload_status(sha: str) -> dict`: `{"sha", "pages", "tesseract_done", "unlimited_done", "failed", "low_confidence", "state": "ocr"|"upgrading"|"ready"}`
  - On disk under `UPLOADS_DIR/<sha>/`: `source.pdf`, `info.json`, `pages/<n>.json` (`PageRecord.to_json`), and `index/` (the Collection).
